# Contracts — frozen as of S0

Everything in this directory is the shared contract between the twelve
workstreams. **Only Workstream A changes it, and only via an ADR.**

| Path | What |
| --- | --- |
| `schema/` | Forward-only numbered Postgres/TimescaleDB migrations |
| `openapi/openapi.yaml` | The HTTP API. The FastAPI implementation must match it. |
| `events/` | MQTT topics and payloads published to Home Assistant |
| `VERSION` | Contract version; bumped by A when a migration or spec change lands |

## Rules

- Migrations are **forward-only** and numbered `NNN_slug.sql`. Never edit a
  migration that has been merged; add a new one.
- Every API path in `openapi.yaml` names the workstream that implements it with
  an `x-workstream` extension, so ownership is machine-checkable.
- Contract tests in `tests/contract/` assert that the running API matches
  `openapi.yaml` and that the database matches the migrations. They run in CI on
  every PR.
- Need a change? Open a PR that adds an ADR under `docs/adr/` describing the
  change and its consumers, and tag A. Do not edit `contracts/` in a feature PR.

## Units and conventions

- All lengths in millimetres, temperatures in °C, volumes in litres internally.
  Display units are a per-user preference resolved in the UI.
- All timestamps are `timestamptz` stored in UTC.
- Identifiers are UUID v7 (time-ordered), generated by the application.
- Enumerations live in the database as `text` with a `CHECK` constraint, not as
  Postgres enums, so they can be extended by a forward-only migration.
