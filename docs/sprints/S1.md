# S1 — Skeleton

**Theme:** a plant can be added by name and appear in the Register.

## Exit criterion

> Add a plant by name; it appears in the Register.

**Met**, on the mock stack and against a real Postgres. Workstream C asserts it
twice — `test_a_plant_added_by_name_appears_in_the_register` and
`test_the_exit_criterion_holds_against_a_real_database`.

Not met: *"…on staging"*. The staging stack on the swarm was Workstream B's S1
deliverable and needs Harbor and swarm credentials this environment does not
have. Carried to S2 as B's first task; it is the only part of S1 that slipped.

## Shipped

**C — Inventory.** Specimen, location and zone CRUD behind a storage seam:
`FixtureRepository` for mock mode, `DatabaseRepository` on Postgres, one router
over both. Mock mode became writable, which is what lets every other workstream
demonstrate "add a plant" without a database. 93 tests.

**D — Botany.** `POST /taxon/resolve` over POWO and GBIF: common names,
misspellings, synonyms resolved to the accepted name, hybrids, cultivars split
off. Confidence only ever falls. 107 tests, none touching the network.

**I — Design system.** Component library v1 — buttons, cards, fields, the
batch-completion checkbox, dialog, empty/stale states, 24 original icons, theme
switcher — plus a two-theme gallery. 202 tests, up from 32.

**A — Integration.** ADRs 0007–0012; the botany router mounted; contract 1.1.0.

## What went wrong, and what it cost

**All three agents died at once on the account rate limit**, at 08:59, with
nothing pushed. They had done roughly 80k output tokens each. The work survived
only because the containers held it until the limit reset at 12:40.

The cause was mine: the briefs said "open a PR when you are done" and never
said "push early". Pushing incomplete work costs nothing and would have
protected all three. **Every brief now says to push before continuing.**

The budget is shared between the agents and the coordinating session, and three
concurrent workstreams plus coordination is about what it sustains. S2 should
not run five.

## What the workstreams caught in the rules

All three hit cases where S0's rules made required work impossible, and all
three escalated rather than working around it. ADR 0011 records the fixes.

The serious one, found by C: **CI ran `pytest tests -q`**, collecting only L's
suite, while rule 2 puts each workstream's tests in its own directory. C's 93
and D's 107 would never have run in CI. Three sprints of that and the contract
suite would have been the only thing standing between us and a broken `main`.

Also: rule 6 told a workstream to edit a file rule 2 forbade it; the component
gallery needed a route and routes belonged to J; the API image never copied
`workers/`; `workers/` was not a package, which aborts any `mypy` run.

**`main` went red for about twenty minutes** after #5 merged: D's test asserted
`cultivar` was the only field outside the contract, and ADR 0012 had just made
it contractual. D noticed and fixed it in #6 without being asked. The lesson is
ordering — a contract change and the code asserting the old contract must land
together or in the right order, and neither of us checked.

**A hidden route escaped the contract check.** D's `/taxon/sources` diagnostic
endpoint uses `include_in_schema=False`, which hides it from the OpenAPI
document — and the contract test compared document to document, so it could
not see it. The endpoint is legitimate and documented; the test was wrong. It
now walks the real route table and requires any undocumented route to be listed
in `UNDOCUMENTED_ON_PURPOSE`, so the exemption is reviewed rather than
invisible.
